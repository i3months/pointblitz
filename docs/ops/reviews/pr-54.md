## 판단

- 배포 범위·버전·방식은 소유자 결정(0044)이다. PR 은 준비만 한다.
  - `release.yml` 은 `v*` 태그 push 에만 돈다.
  - 태그 버전과 워크스페이스 버전이 같은지 확인한 뒤 fmt·clippy·test 를 돌리고, 그다음 publish 한다.
  - 토큰(`CARGO_REGISTRY_TOKEN`)은 소유자만 넣는다. 토큰이 없으면 publish 단계가 실패할 뿐이다.
- crates.io 버전은 지울 수 없으므로 dry-run 을 매 PR 에서 돌리는 것이 맞다.
- core 설명에서 구현되지 않은 "culling, LOD" 를 뺀 것도 맞다(체크리스트 #10).
- **감독은 태그를 push 하지 않는다.** 첫 배포는 소유자가 토큰을 넣고 태그를 push 할 때다.
