PR 의 결론과 같다: 동기화를 30 프레임에 나누면 WebGPU 는 native 와 같은 수준이다. 그러니 P2.5 의 browser `frame_time` 미달은 그리기가 아니라 **"GPU 가 끝났다" 를 아는 비용**(1 px 복사 + `mapAsync` 왕복)이다. `bash scripts/check.sh` 통과, CI SUCCESS.

## 판단

- 방법이 공정하다: 네 구현 모두 같은 batch 방식(N 프레임 연속 제출 → 한 번 동기화 → 프레임당 평균)을 적용했고, batch=1 은 기존 판정 방법 그대로다.
- **판정은 바꾸지 않는다**(결정 0020 방법, SPEC §7.1). browser.md §3 에는 "확인" 표시만 달았다 — PR #21 검토 판단 2 를 해결한다.
- 공개표(P4.6)에는 판정 값(batch=1)과 진단 값(batch=30)을 함께 싣고, 차이가 동기화 방법에서 온다는 각주를 단다.
- WebGL2 는 비용이 CPU 쪽(`render_offscreen` 안, wgpu GL 변환)이라는 결과를 P4.2 에서 이어 가른다.
