## 반려 사유 (높음)

### H1. `pointblitz-core` 가 네트워크 코드에 의존하게 된다 (#6, SPEC §3.1)

- 이 PR 은 재생 서버 클라이언트(`std::net::TcpStream` 으로 SSE·HTTP 를 다루는 코드)를 `pointblitz-io::client` 로 옮기고, `pointblitz-io` 에 `serde_json` 을 더했다(wasm 이 아닐 때).
- `pointblitz-core` 는 `pointblitz-io` 에 의존한다. 그래서 core 의 의존 트리에 네트워크 클라이언트와 `serde_json` 이 들어온다 — `cargo tree -p pointblitz-core -e normal` 에 `serde_json` 이 나온다(감독 확인).
- SPEC §3.1: `pointblitz-core` 가 "의존해서는 안 되는 것: 창, **네트워크**, 브라우저 API". `pointblitz-io` 의 책임은 "PLY 스트림 파서, 청크 직렬화 형식" 이다. 결정 0003 도 "core 는 네트워크에 의존하지 않는다" 를 정했다.
- **고칠 것**(권장 — SPEC 의 크레이트 목록을 바꾸지 않는 방법):
  1. `pointblitz-io` 에 **기본 꺼진 cargo 기능** `client` 를 두고, `client` 모듈과 `serde_json` 을 그 기능 뒤에 둔다. `pointblitz-native`·`pointblitz-server` 만 `features = ["client"]` 로 켠다.
  2. `cargo tree -p pointblitz-core -e normal` 에 `serde_json` 이 없고, core 가 `client` 를 켜지 않음을 확인한다. 가능하면 `scripts/check.sh` 에 이 검사를 넣는다(예: core 트리에 `serde_json` 이 있으면 실패).
  3. 0036 에 "io 의 `client` 기능(기본 꺼짐)은 core 가 쓰지 않는다 — SPEC §3.1 경계" 를 적는다.
  - 별도 크레이트로 떼는 방법도 가능하다. 다만 SPEC §3.1 의 크레이트 표를 바꾸게 되므로 결정 기록과 SPEC 변경이 함께 필요하다. 기능 플래그 쪽이 가볍다.
