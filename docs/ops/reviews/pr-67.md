- 대상 커밋: `56c6b2b`
- 결과: **통과 — 중간 결과로 병합(판정 보류 항목 있음)**

## 확인

- 표 2·3 의 값(미리보기·정밀·cold·mem_cpu·멈춤·JS 힙, 10 대상)을 감독이 p48 원 기록에서 다시 계산했고 모두 같다.
- 판정 규칙(b342fd3)의 커밋 시각이 재측정 시작 1~2 분 뒤라는 점과 끝난 실행 수(6)를 0048 에 정직하게 적었다.
- 결과가 PointBlitz 에 불리한 내용(구조의 몫이 거의 전부, 같은 API 지연 몫은 흔들림 안, WebGL2 그리기는 three.js 가 빠름, 해석은 JS 워커가 더 빠름)을 그대로 실었다.

## 판정 보류 — 추가 실험(감독 지시, 결정 0049 로)

1. **PointBlitz webgl frame_time 측정 결함**(화면 밖 텍스처에 그리고 캔버스를 읽어 동기화가 기다리지 않음). P4.6 부터 있었고 공개된 webgl frame_time(3.5/6.0/13.5 ms)은 무효다. 고친 뒤 다시 잰다.
2. **WebGPU frame_time 두 모드**는 원인 미확인이다(규칙 (나)). 그리기 판정을 동기화 산물과 떼기 위해, 모든 대상을 batch=30 처리량(가능하면 GPU timestamp 보조)으로 다시 잰다.
3. **같은 API 지연의 Rust 몫**이 실행 3~5 회의 흔들림과 겹친다. replay·cold 10 회와 미리 정한 통계 판정(중앙값 비 + 부트스트랩 95 % 구간)으로 확정한다.
