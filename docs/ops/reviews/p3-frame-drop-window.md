# 서버 영상 "프레임 빠짐" 측정 구간 — 감독 결정(SPEC 해석, 소유자 위임)

- 날짜: 2026-10-08
- 결정한 사람: 감독(소유자 위임, 2026-10-07). SPEC 값을 바꾸는 것이 아니라 SPEC §7.1 표의 정의를 측정 전에 해석해 고정한다.
- 계기: PR #27(P3.3) 의 cold 2 초 실행에서 프레임 빠짐 6.57~9.6 %(시작 구간이 큰 몫), replay ×60 에서 1.05~1.24 %.

## 결정

- 판정 시나리오: **`orbit`** — SPEC §7.1 표가 "영상 프레임 빠짐(orbit) ≤ 1 %" 로 이미 정했다.
- 측정 구간: **첫 영상 프레임을 화면(캔버스)에 그린 뒤부터 orbit 이 끝날 때까지.** 첫 프레임 전 주기(연결·디코더 설정)는 빠짐으로 세지 않는다 — 그것은 `first_frame`/cold 지표가 다룬다.
- 정의는 SPEC 그대로: 클라이언트 60 Hz 주기 중 새 영상 프레임이 그려지지 않은 주기의 비율(서버 생성·전송·디코딩 지연을 모두 포함하는 끝에서 끝까지 값).
- `replay`·`cold` 의 빠짐 비율은 **보고만** 한다.
- `serve` 에 `orbit` 시나리오(고정 시점 8곳 순회 또는 개관 시점 둘레 회전, 다른 대상의 `orbit` 과 같은 데이터·시점)가 없으면 P3.4 측정 **전에** 만들고 결정 기록에 적는다.
