# PR #22 검토 노트 — TASKS: P3(server video) 쪼개기 + 목표 수치 제안

- 검토일: 2026-10-08
- 대상 커밋: `fd61ca7`
- 결과: **통과**(문서만)

## 확인

- 범위가 SPEC §7 P3(헤드리스 + NVENC + WebSocket/WebCodecs, 완료 기준 비교표 server video 열)·결정 0010 과 같다. 새 범위 없음. WebRTC 는 0010 대로 P3 이후로 남겼다.
- P3.0 을 측정(P3.4) **전에** 끝내도록 순서를 둔 것이 맞다(SPEC §8.1). 제안 문서는 `docs/notes/` 에 "제안" 으로 두고 SPEC 은 건드리지 않았다.
- 목표 수치는 소유자 몫이다. 작업자가 소유자에게 직접 확인을 요청했다. 소유자 위임(2026-10-07)에 따라, **P3.4 측정 시작 전까지 소유자 답이 없으면 감독이 정한다**(P0.7 과 같은 방식).

## 감독 의견 (P3.0 결정에 쓸 것)

| 항목 | 의견 |
|---|---|
| 지연 목표(+30~50 ms) | 인코딩·전송·디코딩·다음 영상 프레임을 더한 근거가 명확하다. 동의 |
| 입력 → 표시 p50/p95 ≤ 50/80 ms | 동의. 루프백·같은 PC 조건임을 목표 옆에 적는다 |
| 60 fps · 드롭 ≤ 1 % | 동의. "드롭" 의 정의(서버가 못 만든 프레임 / 클라이언트가 못 그린 프레임)를 P3.0 에서 하나로 정한다 |
| 화질 SSIM ≥ 0.95 | 비교 대상은 작업자 의견대로 **native 캡처 대비**(사용자가 보는 결과)가 맞다. 인코딩 전 프레임 대비는 진단값으로 함께 싣는다 |
| 클라이언트 `main_thread_block` 0 회 | 동의 |
| 비트레이트·바이트·메모리 기록만 | INTENT 원칙 2 와 같다 |

## 기록만 (P3.1 결정 기록에서 다룰 것)

| 수준 | 내용 |
|---|---|
| 중간(라이선스, #7 은 치명) | 인코더 경로 비교에 라이선스를 반드시 넣는다. ffmpeg 는 빌드에 따라 LGPL 또는 **GPL** 이다(배포되는 Windows 빌드는 GPL 이 흔하다). 외부 프로세스로 부르기만 하고 배포물에 넣지 않는 경우와, 배포물에 포함하거나 링크하는 경우를 나눠 적는다. NVENC 직접 호출은 NVIDIA Video Codec SDK 헤더의 라이선스 조건을 확인한다. GPL·AGPL 이 배포물에 들어가는 선택은 할 수 없다(SPEC §8.2). |
| 중간 | ffmpeg 를 받는 것(외부 바이너리 다운로드)은 되돌리기 쉬운 로컬 작업이지만, 측정·배포 경로에 들어가면 공개 재현 방법이 된다. 출처(공식 빌드)·버전·해시를 결정 기록에 남긴다. 소유자 위임 범위 안이라 감독이 승인한다 — 단 위 라이선스 조건을 먼저 정리한다. |
| 낮음 | 서버와 브라우저가 같은 PC·같은 GPU 를 쓰면 서로의 GPU 시간이 섞인다. P3.4 문서에 이 조건과 함께 "서버 렌더·인코딩 GPU 시간" 을 따로 기록한다(이미 제안에 있음). |
