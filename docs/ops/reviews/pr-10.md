## 판단: 점 모양 — ②(기준 방식 밉맵 끔)를 받아들인다

PR #9 검토에서 감독은 ①(PointBlitz 를 2×2 에 맞춤)을 권했다. 작업자는 ②를 골랐고 그 근거가 더 낫다.
- 밉맵은 모양뿐 아니라 **모든 점 색을 약 10 % 어둡게** 했다. ①을 택하면 이 결함까지 흉내 내야 한다. 그러면 결정 0007("PLY 색 그대로")과 "three.js 를 제대로 쓴 기준" 둘 다 어긋난다.
- ② 뒤 SSIM 이 0.9425 → 0.9919 로 올라 화질 비교가 의미를 갖는다.
- 성능 차이는 A/B 로 실행 간 범위 안임을 작업자와 감독이 각각 확인했다. P0.6 수치를 그대로 두고, 목표에는 더 엄격한 P0.6 값을 쓰는 것도 타당하다.
- 0019 는 본문을 바꾸지 않고 정정 표시만 했다 — PROJECT §4 준수.

## SSIM 목표를 넣지 않은 것

**받아들인다.** 이미 잰 값을 보고 목표를 정하면 사후 기준이 된다(SPEC §8.1). SSIM 은 "두 구현이 같은 화면을 그린다" 는 공정성 확인용으로 보고만 한다.
