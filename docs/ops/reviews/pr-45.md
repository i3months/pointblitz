## 판단

- 감독 규칙(PR #44 검토)대로 **위상 잠금은 끔으로 확정**, 더 다듬지 않는다. 측정 전에 0042 에 다듬기 내용을 적었고, 결과를 본 뒤 측정 구간 정의를 바꾸지 않았다 — 맞다.
- **감독 제안 정정**: PR #44 노트의 "목표 φ ≈ 0.2(rAF 직후)" 는 틀렸다. rAF 밖에서 그린 프레임은 다음 갱신에 나가므로 대기 = (1 − φ) × 주기이고, 0.2 는 대기를 늘리는 쪽이다. 작업자가 데이터(위상 구간별 대기·빈 주기 비율)로 0.65 를 고른 것이 맞다.
- 오차를 감싸지 않게 한 것(목표 ≠ 0.5 에서 경계를 가로지르지 않게)과 거부 기준을 한 주기로 넓힌 것도 타당하다.
- **SPEC 영향**: 기본(쓰기 스레드·끔)의 orbit 빠짐은 실행마다 0.26~6.32 %(작업자 3/5, 감독 1/1 > 1 %)다. SPEC §7.1 "프레임 빠짐 ≤ 1 %" 는 미달 쪽이다. P4.6 에서 실측 그대로 실행별 분포와 함께 판정하고, 원인(서버 60 Hz 와 화면 약 59.94 Hz 의 위상 흐름)을 각주로 단다. 목표는 바꾸지 않는다.
