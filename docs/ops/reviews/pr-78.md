## 확인한 것

- ④ 선택: 고정 규칙(8 곳 모두 SSIM ≥ 0.999 인 작은 쪽, 둘 다 못 지키면 v2-12)대로 v2-12. 실제 전달 청크(③ 순서 정밀 전체 + 미리보기 차분)에서 쟀고, 청크 상자 변·좌표 간격(정밀 1.69–1.72 mm, 최대 오차 0.87 mm / 차분 0.48 mm, 0.24 mm)을 실었다. 원인 나누기(순서만 바꿔도 0.999 아래, 차이 픽셀이 점 영역 1 px 팽창 안 99.998–100 %)는 기준 변경이 아니라 근거 보충으로 적혔다. v2-8 은 다시 볼 조건으로 남았다(기준은 측정 전에 정함).
- ③: 전체 전달만 8 개마다 하나 순서(비트 뒤집기 0,4,2,6,1,5,3,7), 첫 패스 끝 청크에 `FLAG_FIRST_PASS_COMPLETE`, 차분은 파일 순서 그대로. `Scene::insert` 가 첫 패스 표시에서 새 세대로 바꾸고 나머지를 같은 세대에 채운다.
- 같은 API 공정성: B1(a·b·webgpu)도 v2-12 를 해석 없이 받고(정규화 u16 + 객체 위치·크기), 첫 패스 표시에서 바꾼다. `event_first_latency` 는 PointBlitz 와 B1 이 같은 정의(첫 패스가 처음 보인 프레임, GPU 끝 동기화)로 기록한다. B2 는 그대로.
- 셰이더: 청크마다 `offset = 원점 + 상자 최소 − 카메라`(f64 로 계산), `scale = 상자 ÷ 65535` — 카메라 상대 좌표 원칙(0013) 유지.
- 시험(감독 재실행): `cargo test -p pointblitz-io -p pointblitz-core -p pointblitz-bench` 모두 통과, `web/chunks.test.mjs` 4/4. CI 세 작업 통과.
