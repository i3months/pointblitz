# 0022 청크 형식 v1 세부

- 상태: 승인
- 날짜: 2026-10-07
- 결정한 사람: 작업자 제안 → 감독 승인(PR #8 검토, 2026-10-07)

## 맥락
결정 0008 은 "점당 16 B 무압축, GPU 레이아웃 그대로" 를 정했고, 결정 0009 는 세대(generation) 단위 추가·교체를 정했다.
P1.1 에서 바이트 배치를 확정한다. 형식 정의는 `crates/io/src/chunk.rs` 머리 주석이 단일 출처다.

## 선택지와 결정
| 항목 | 선택지 | 고른 것 | 이유 |
|---|---|---|---|
| 점 배치 | SoA(위치 배열 + 색 배열) / **AoS 교차(위치 f32×3 + 색 u8×4)** | AoS | 받은 바이트 하나가 그대로 정점 버퍼 하나(보폭 16, `Float32x3` @0, `Unorm8x4` @12). 업로드 한 번, 버퍼 바인딩 하나. SoA 는 버퍼 둘을 만들거나 분리 복사가 필요하다 |
| 색 | u8×3(15 B, 정렬 깨짐) / **u8×4, a = 255** | u8×4 | 16 B 정렬. 남는 바이트는 나중에 선택·강조 플래그로 쓸 수 있다 |
| 위치 기준 | 절대 좌표 f32 / **청크마다 원점(f64) + 상대 f32** | 상대 | 결정 0013(원점에서 먼 좌표의 f32 오차). 원점은 경계 상자 중심을 1 m 로 반올림 — 읽기 쉽고 f64 로 정확. 원점에서 5 km 떨어진 점도 입력 f32 값이 그대로 복원된다(시험) |
| 헤더 | 가변 길이(JSON 등) / **고정 80 B 이진** | 고정 80 B | 해석 비용 0 에 가깝고 몸통이 16 B 정렬로 시작한다. 길이 필드를 넣어 v2 에서 늘릴 수 있다 |
| 헤더 필드 | — | magic `PBCK`, version, header_len, generation, index, point_count, flags, origin f64×3, bbox min·max f32×3(원점 기준), 예약 8 B | 컬링(경계 상자)과 세대 교체(generation·flags)에 필요한 것만 |
| 세대 끝 표시 | 별도 메시지 / **flags bit 0 (`LAST_IN_GENERATION`)** | 플래그 | 청크 흐름만으로 "이 세대를 다 받았으니 교체해도 된다" 를 안다 |
| 바이트 순서 | — | 리틀 엔디언 | 대상 플랫폼(x86·ARM·wasm) 모두 LE. GPU 버퍼도 LE |
| 청크 크기 | 스냅샷 하나 = 청크 하나 / **최대 256 Ki 점(약 4 MiB)** | 256 Ki | 큰 스냅샷도 잘라 보내 첫 청크부터 바로 그릴 수 있고(업로드·그리기를 겹침), 경계 상자 단위 컬링의 단위가 된다. 값은 P1 측정 뒤 다시 본다 |
| 검증 | — | magic·version·header_len·길이 = 80 + 16·n, 곱셈 넘침 검사 | 잘린·변조된 입력을 GPU 에 올리지 않는다 |

## 결과 (`flight-01`, 네이티브 release, i7-13700F — `cargo test -p pointblitz-io --release --test flight01 -- --nocapture`, `PB_FLIGHT01` 필요)

| 스냅샷 | 점 | PLY | 청크 합 | 청크 수 | PLY 해석 | 청크 변환 |
|---|---:|---:|---:|---:|---:|---:|
| event_01 | 151,510 | 4,091,016 B | 2,424,240 B | 1 | 1.2 ms | 2.1 ms |
| event_14 | 2,502,015 | 67,554,652 B | 40,033,040 B | 10 | 19.7 ms | 33.7 ms |

- 14 개 모두 점 수가 SPEC §2.2 와 같고, 64 KiB 조각 스트리밍 결과가 통째 해석과 같다.
- 청크 합은 PLY 의 59 %(법선을 빼서). 변환은 서버에서 한 번만 한다 — 클라이언트는 해석하지 않는다.
- 참고(같은 파일, 다른 환경이라 직접 비교값 아님): 기준 방식 `PLYLoader.parse` 는 브라우저 메인 스레드에서 711 ms(docs/bench/baseline-three.md).

## 대가
- 법선이 필요한 기능(조명 등)은 별도 버퍼·별도 형식이 필요하다(결정 0008).
- 교차 배치라 위치만 따로 읽는 처리(CPU 컬링 등)는 보폭 16 으로 건너뛰며 읽어야 한다.
