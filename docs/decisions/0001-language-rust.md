# 0001 구현 언어: Rust

- 상태: 승인
- 날짜: 2026-10-07
- 결정한 사람: 소유자

## 맥락
렌더 코어 하나를 브라우저(wasm)·네이티브·서버에서 같이 돌려야 하고, 나중에 다른 SkyLens 라이브러리(파이썬 포함)와 합쳐야 한다.
이전 시도(skylens-renderer)는 Node.js 22 로 서버 가공을 했고 렌더링은 브라우저 WebGL2 에 맡겼다.

## 선택지
| 선택지 | 장점 | 단점 | 근거 |
|---|---|---|---|
| **Rust** | 네이티브 성능, wasm 1급 지원, wgpu 생태계, pyo3 로 파이썬 연동, skyrecon 과 같은 언어 | 학습·컴파일 시간 | 같은 알고리즘(100만 점 투영 + z 버퍼, 단일 스레드) 측정에서 Rust 25.0~31.7 ms, Node 37.9~49.4 ms(이전 리포 결정 0009). skyrecon 이 2026-10-07 Rust 워크스페이스로 전환 |
| C++ | 성능 최상, 그래픽 생태계 큼 | wasm 빌드·패키징 번거로움, 메모리 안전성 부담, 팀 스택과 다름 | 같은 측정 20.9~25.2 ms |
| Node.js / TypeScript | 웹 생태계와 바로 연결 | 브라우저 밖에서 GPU 를 직접 다루지 못함, 파이썬 연동 불편, 성능 열세 | 위 측정 |
| Python | 연동 쉬움 | 렌더 코어로는 느림 | 같은 측정 178~252 ms |

## 결정
Rust 로 렌더 코어와 모든 실행 위치를 만든다. 비교용 기준 방식(three.js)만 JS 로 둔다.

## 대가
- 웹 쪽은 wasm 경계(복사·바인딩 비용)를 관리해야 한다.
- Node 로 만든 이전 코드(약 5,900 시험)는 재사용하지 않는다. 규칙과 측정 방법만 가져온다.

## 다시 볼 조건
- wasm 경계 비용이 측정에서 지배적이면 경계 설계를 다시 본다(언어 자체는 유지).
