# 0047 릴리스를 이어서 올릴 수 있게(이미 있는 버전은 건너뜀)

- 상태: **승인**(감독, PR #58 검토 2026-10-08)
- 날짜: 2026-10-08
- 결정한 사람: 감독(방향: 이미 있는 버전 건너뛰기, 태그는 다시 달지 않음), 작업자(방법)
- 관련: 결정 0044(crates.io 배포), 0046

## 맥락
- v0.1.0 릴리스(실행 37768796953, 태그 → 8b8cb79) 두 번째 시도에서 6 개 중 5 개(`pointblitz-io`, `-core`, `pointblitz`, `-native`, `-server`)가 0.1.0 으로 올라갔고, `pointblitz-web` 은 crates.io 의 새 크레이트 수 제한(429, 13:01:48 UTC 뒤에 다시)에 걸렸다.
- 같은 실행을 다시 돌리면 `cargo publish --workspace` 가 이미 올라간 크레이트에서 먼저 실패한다.
- 태그를 다른 커밋으로 옮기면 이미 배포된 0.1.0 다섯 개의 출처 커밋(8b8cb79)과 태그가 어긋난다 — 하지 않는다.

## 결정
| 항목 | 고른 것 | 이유 |
|---|---|---|
| publish 단계 | 크레이트마다(의존 순서: io → core → pointblitz → native → server → web) crates.io API 로 그 버전이 있는지 보고, 있으면 건너뛰고 없으면 `cargo publish -p` | 부분 실패를 같은 방법으로 이어서 끝낼 수 있다 |
| 다시 돌리기 | `workflow_dispatch`(입력 `tag`): 워크플로 파일은 main 것을 쓰고, **코드는 그 태그를 체크아웃** | 태그를 옮기지 않고 같은 출처 커밋에서 나머지를 올린다 |
| 버전 확인 | 태그(입력 또는 푸시된 태그) = 워크스페이스 버전 | 그대로 |
| 다음 할 일 | 병합 뒤 13:01:48 UTC 이후, 소유자 확인을 받고 `tag = v0.1.0` 으로 수동 실행 → `pointblitz-web` 만 올라간다 | |
