# 0043 Linux NVENC와 두 번째 장비(V100) 측정

- 상태: **승인**(감독, PR #51 검토 2026-10-08)
- 날짜: 2026-10-08
- 결정한 사람: 소유자(Linux NVENC 를 추가해 V100 에서 인코딩까지 잰다, 서버 홈에 Rust 설치 허용 — 2026-10-08 채팅), 작업자(구현·측정 방법)
- 관련: 결정 0011(비용 모델), 0035(NVENC 직접), 0038·0040·0041(측정 유효성), docs/bench/cost-model.md

## 맥락
- P4.5 비용 모델은 두 장비로 계수를 맞춘다(결정 0011). 두 번째 장비는 V100 서버(소유자 제공 — Tesla V100-PCIE-16GB, Linux, 16 코어)다. 접속 정보는 저장소에 적지 않는다.
- 서버 영상의 NVENC 는 Windows 에서만 됐다(결정 0035: `nvEncodeAPI64.dll`·`nvcuda.dll` 을 실행 중 로드).
- 서버에는 화면·브라우저가 없다(헤드리스). native 창·브라우저 대상은 거기서 잴 수 없다.

## 결정
| 항목 | 고른 것 | 이유 |
|---|---|---|
| Linux NVENC | 같은 코드에서 라이브러리 이름만 OS 별로: `libnvidia-encode.so.1`, `libcuda.so.1`. `serve`·`encode-test` 를 Linux 에서도 빌드 | NVENC API·CUDA 드라이버 API 는 두 OS 에서 같다. 드라이버가 라이브러리를 깔아 둔다(빌드에 SDK·CUDA 툴킷 불필요는 그대로) |
| 바인딩 | 받아 온 Windows 바인딩의 `LONG`(Windows `long`)과 `_GUID::Data1`(`unsigned long`)을 `i32`·`u32` 로 | Windows 에서 둘 다 32 비트라 배치가 같고, Linux 헤더는 이 자리가 32 비트 정수다. 그대로 두면 Linux 에서 64 비트가 돼 구조체 배치가 틀린다 |
| 두 장비에서 재는 것(같은 방법) | ① 청크 변환·전송: 재생 서버 + `/chunks/14`(마지막 스냅샷 전체 40.0 MB)를 HTTP 로 5 회 받음 → 서버 로그의 읽기·합계 ms. ② 서버 렌더·인코딩: `serve --orbit` + `probe`(헤드리스 클라이언트) 5 회 → 틱마다 렌더(그리기 + 읽어 오기)·인코딩 ms. ③ 인코딩만: `encode-test`(고정 시점 + 회전) | 헤드리스로 두 장비에서 똑같이 잴 수 있는 것. 클라이언트가 디코딩하지 않으므로 GPU 를 나누지 않는다 — RTX 4070 쪽도 같은 방법으로 다시 잰다(P3.4 값은 브라우저가 같은 GPU 에서 디코딩) |
| 유효성(서버) | C1: 실행 전 GPU 사용률(`nvidia-smi`). **공유 장비 규칙(감독, PR #51 검토)**: 다른 사람의 프로세스는 멈추지 않고 기다리거나 그 작업들의 GPU 잠금을 쓴다. 멈춰야 하면 그때마다 소유자가 직접 지시한 경우에만, `ps` 로 PID 를 확인한 뒤 멈춘다. 끝나면 잠금과 자기 프로세스를 정리했는지 보고한다. C3: 해당 없음(화면 없음, 서버 틱 60 Hz 는 서버 시계). C4: 같은 보정 루프를 Linux 에서 못 돌리므로 **CPU 보정 대신 실행 중 CPU 주파수·부하를 기록**(`/proc/cpuinfo`, `uptime`)하고 C4 미상으로 표시 | 측정 도구(measure-env.ps1)는 Windows 전용이다 |
| 다른 작업과 겹침 | 서버에서 다른 GPU 작업(예: COLMAP)이 돌면 빌드·측정하지 않고 기다린다 | 그 작업의 시간 측정을 흔들지 않기 위해 |

## 대가
- 두 장비의 "그리기" 는 headless 렌더 + 화면 읽어 오기(8 MB) 합이라 native 창의 frame_time 과 같은 양이 아니다. 비용 모델의 그리기 계수는 두 장비의 같은 양(서버 렌더 ms)의 비로 맞추고, native frame_time 과의 관계는 RTX 4070 한 대에서 잰 비로 옮긴다.
- 서버 쪽 C4 는 미상이다.

## 결과 (2026-10-08, docs/bench/cost-model.md §4)
- Linux NVENC: V100 서버에서 `encode-test`·`serve` 동작, 출력을 ffmpeg 로 디코딩 — 240 프레임 × 2 스트림 오류 0. ubuntu CI 는 GPU 없이 컴파일·단위 시험(바인딩 배치 시험 포함).
- 두 장비 비(V100 ÷ RTX 4070): CPU 청크 만들기 약 2.6, 서버 렌더 약 1.0, 인코딩만 1.28, NVENC 입력 복사 2.9.
- **사고**: 첫 V100 측정은 같은 계정의 다른 GPU 작업과 겹쳐 버렸다. 소유자 지시("그 작업 중지, 내 작업 우선")로 소유자 계정의 다른 GPU 작업을 PID 로 멈췄으나 그쪽 세션이 곧 다시 띄웠고, 그 작업들이 쓰는 `flock` GPU 잠금을 잡은 채 다시 재서 겹침 없이 끝냈다. 도중에 작업자의 `pgrep -f` 패턴이 자기 ssh 명령 줄에도 맞아 자기 셸에 신호를 보낸 실수가 있었다(측정 프로세스는 살아 있었음) — 앞으로는 PID 를 `ps` 로 확인한 뒤 그 PID 만 멈춘다.
- 대가 절 보충: 서버 쪽은 다른 사용자 작업과 GPU 를 나누는 장비라, 측정은 그 작업들의 GPU 잠금을 잡고 한다.
