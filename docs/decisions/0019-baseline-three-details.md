# 0019 기준 방식(three.js) 구현 세부와 실행 환경

- 상태: 승인
- 날짜: 2026-10-07
- 결정한 사람: 작업자 제안 → 감독 승인(PR #5 검토, 2026-10-07)

## 맥락
P0.4. 결정 0005 가 기준 방식의 큰 틀(three.js 0.185 + `PLYLoader` + `Points`, 이벤트마다 전체 다운로드·메인 스레드 해석·전체 교체)을 정했다.
같은 화면(결정 0007)을 내기 위한 세부와, 측정을 돌릴 브라우저 환경을 정한다.

## 선택지와 결정
| 항목 | 선택지 | 고른 것 | 이유 |
|---|---|---|---|
| 원형 점 | `ShaderMaterial` 직접 작성 / **`PointsMaterial` + 원판 텍스처 `map` + `alphaTest 0.5`** | 후자 | three.js 사용자가 원형 점을 만드는 흔한 방법이고 `PointsMaterial` 을 유지한다(결정 0005). 셰이더를 직접 쓰면 "기존 방식" 이 아니다. PR #1 감독 의견 반영 |
| 안티앨리어싱 | MSAA 켬(skylens 현황판 기본) / **끔** | 끔 | PointBlitz 와 같은 조건(결정 0007 고정 2 px 원). MSAA 비용은 두 구현에 같이 켜서 따로 잴 수 있다 |
| 장치 픽셀 비 | 기기 값 / **1 고정** | 1 | 결정 0007 측정 해상도 1920×1080 |
| 좌표 | 데이터를 y 위로 변환 / **`camera.up = +z`** | 후자 | 데이터는 ENU 그대로(결정 0013). three.js 는 카메라 위 방향만 바꾸면 된다 |
| 이벤트 처리 | 최신만 반영 / **도착 순서대로 모두** | 순서대로 | 앱이 하는 방식. 앞 해석이 늦으면 뒤 이벤트도 늦어지는 효과까지 기준에 포함된다 |
| 렌더 루프 | 변경 시에만 / **매 프레임** | 매 프레임 | three.js 앱의 일반적 루프(skylens 도 매 프레임 렌더) |
| 측정 브라우저 | Playwright 내장 Chromium / **설치된 Chrome + playwright-core** | 설치된 Chrome 155 | 사용자가 실제로 쓰는 브라우저. 브라우저를 따로 내려받지 않는다 |
| GPU | 기본(헤드리스는 SwiftShader 로 떨어질 수 있음) / **`--use-angle=d3d11 --enable-gpu --ignore-gpu-blocklist`** | 후자 | 실제 GPU 로 그린다. 렌더러 문자열을 결과에 기록해 소프트웨어 렌더링이 섞이면 드러나게 한다 |
| 측정 훅 | DevTools 트레이스만 / **페이지 안 `window.__pb`(performance.now 표식) + 이후 CDP** | 둘 다 | 이벤트 단계(받음·다운로드 끝·해석 끝·교체·화면 반영)는 페이지만 안다. 메인 스레드 블록·힙은 P0.5 에서 CDP 로 잰다 |

의존성(벤치 전용, 배포물에 포함하지 않음): `three` 0.185.1(MIT), `playwright-core` 1.63.0(Apache-2.0).

## 대가
- 원판 텍스처 + alphaTest 는 프래그먼트에서 텍스처 읽기와 discard 를 한다. PointBlitz 의 원형 처리(결정 0006)와 비용 구조가 다를 수 있으므로 비교표에 함께 적는다.
- 루프백 서버라 다운로드 시간은 네트워크를 반영하지 않는다. 네트워크 비용은 바이트 × 대역폭 모델(결정 0011)로 더한다.
