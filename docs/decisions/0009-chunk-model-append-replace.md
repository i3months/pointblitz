# 0009 갱신 모델: preview 는 추가, refined 는 세대 교체

- 상태: 승인
- 날짜: 2026-10-07
- 결정한 사람: 작업자 제안 → 감독 동의(PR #1 검토) → 소유자 승인(2026-10-07)

## 맥락
`flight-01` 분석([docs/data/flight-01.md](../data/flight-01.md)): preview 스냅샷은 직전 스냅샷 + 새 점(직전 점 100 % 비트 동일),
refined 스냅샷은 직전과 비트 동일 점 0 개이고 초반에는 좌표계 원점까지 옮겨진다.

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| **추가 + 세대 교체** | preview 는 새 점(2~5만)만 보내고 올림. refined 는 이전 세대를 그리는 동안 새 세대를 올리고 한 번에 바꿈(빈 화면 없음) | 교체 순간 GPU 메모리 두 배 |
| 매번 전체 교체 | 단순, 기준 방식과 같음 | preview 이득 없음 |
| refined 를 "변환 + 차분" 으로 | 전송·업로드 최소 | 점을 다시 계산하므로 성립하지 않음(실측) |

## 결정
`Scene` 은 세대(generation) 단위로 청크를 관리한다. preview 는 현재 세대에 추가, refined 는 새 세대를 만들어 다 받으면 교체한다.

## 대가
- 교체 중 최대 GPU 메모리 ≈ 이전 세대 + 새 세대(250만 점 × 16 B × 2 ≈ 80 MB).

## 다시 볼 조건
- skyrecon 이 구역 단위 결과(`full/{preview,refined}/…_KK_pos….ply`)를 노출하면 구역 단위 교체로 바꾼다.
- `--fixed-enu-origin` 으로 원점이 고정되면 refined 사이 이동이 줄어 다른 최적화가 가능할 수 있다.
