# 0016 툴체인·워크스페이스·CI

- 상태: 제안
- 날짜: 2026-10-07
- 결정한 사람: 작업자(제안) → 감독 검토

## 맥락
P0.1. 크레이트 경계(SPEC §3.1)를 처음부터 코드 구조로 고정하고, 매 PR 이 같은 조건에서 검증되게 한다.

## 선택지
| 항목 | 선택지 | 고른 것 | 이유 |
|---|---|---|---|
| 툴체인 | stable 최신 고정 / stable 떠다님 / nightly | **1.99.0 고정**(`rust-toolchain.toml`) | 측정 재현성 — 컴파일러가 바뀌면 성능 수치도 바뀐다. 올릴 때는 PR 로 올린다 |
| MSRV | 낮게 선언 / 고정 툴체인과 같게 | **1.99**(`rust-version`) | 낮은 MSRV 를 선언하려면 CI 에서 그 버전으로 시험해야 한다. 지금은 시험하지 않으므로 같게 둔다. 공개 전에 다시 본다 |
| 에디션 | 2021 / 2024 | **2024** | 새 프로젝트, 최신 규칙. skyrecon(2021)과 의존 관계는 크레이트 단위라 문제없다 |
| 구조 | 크레이트 하나 + 모듈 / 워크스페이스 | **워크스페이스 6 크레이트** | 크레이트 경계로 의존 규칙(core 는 창·네트워크 금지)을 컴파일러가 강제한다 |
| unsafe | 허용 / 금지 | **`unsafe_code = "deny"`(워크스페이스 린트)** | 필요해지면 그 크레이트에서만 결정 기록과 함께 푼다 |
| CI | GitHub Actions / 로컬만 | **GitHub Actions, ubuntu·windows** | 공개 리포의 신뢰 신호. fmt·clippy(-D warnings)·build·test·wasm32 check |
| wasm 확인 | 빌드 도구(wasm-pack) / `cargo check --target wasm32` | **`cargo check` 만** | P2 전까지는 core·io·web 이 wasm 으로 컴파일되는지만 지킨다. 패키징 도구는 P2 에서 정한다 |

GPU 가 필요한 시험은 CI(GPU 없음)에서 돌지 않는다. GPU 시험은 기능 플래그로 분리하고 로컬(감독 재현)에서 돌린다 — P1 에서 정한다.

## 대가
- 툴체인을 고정하면 새 기능을 쓰려면 PR 로 올려야 한다.
