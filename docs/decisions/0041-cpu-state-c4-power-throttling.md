# 0041 측정 CPU 상태(C4)와 Windows 전원 조절 끄기(측정 프로세스만)

- 상태: 구현·측정 끝, 감독 검토 대기
- 날짜: 2026-10-08
- 결정한 사람: 감독(C4 규칙을 측정 전에 정할 것, 전원 조절 후보), 작업자(규칙 값, 구현)
- 관련: 결정 0038(C1·C2), 0040(C3, keep-display), docs/bench/baseline-three.md 재측정 절

## 맥락
- 13:50 무렵부터 같은 일이 느려졌다: three.js replay ×60 해석 속도가 셋째 스냅샷부터 절반(43 대 85 MB/s), 감독의 PR #38 재현에서 서버 틱 p95 23.5 ms·최대 46 ms(빠짐 9–15 %). C1~C3 는 이것을 못 잡았고, C2 는 같은 세션 중앙값과 비교해 세션 전체가 느리면 못 잡는다.
- **원인 확인**: Windows 전원 조절(EcoQoS). 백그라운드 프로세스의 바쁜 스레드를 약 3 초 뒤 효율 코어(이 PC 의 CPU 16–23)로 옮긴다. 같은 단일 스레드 루프가 성능 코어 12,650 회/s → 효율 코어로 옮겨진 뒤 8,000–8,500 회/s. 그 프로세스만 전원 조절을 끄면(SetProcessInformation, ProcessPowerThrottling, 실행 속도) 6 초 내내 성능 코어에서 12,650 회/s.
- 끄고 다시 잰 three.js replay ×60(14:1x): preview / refined p50 453 / 627 ms, 해석 합계 6.1 s — P3.4(456 / 641 ms, 6.26 s)와 같다. 오전 측정이 정상이었던 것은 소유자가 PC 를 쓰는 동안 Windows 가 이 조절을 덜 걸었기 때문으로 본다(확인 안 함).

## 결정
| 항목 | 고른 것 | 이유 |
|---|---|---|
| 전원 조절 끄기 | `bench/measure-env.ps1`(keep-display 를 넓힘)이 실행 동안 1 초마다 **실행의 프로세스**에 전원 조절을 끈다: gpu-watch 의 자손(하네스·Playwright 가 띄운 Chrome·서버·native) + 이 저장소의 빌드 산출물(`target\release` 의 실행 파일, 예: 재생 서버). 그 밖의 프로세스(소유자의 Chrome 등)는 건드리지 않는다 | 프로세스 단위 설정이라 시스템 설정 변경이 아니고 프로세스가 끝나면 사라진다(감독 의견과 같음). 측정 대상과 기준 방식에 똑같이 건다 |
| **C4** | 실행 직전 고정 단일 스레드 보정 루프(200 ms × 3 의 최댓값, 전원 조절 끈 상태)가 **기준(`bench/cpu-reference.json` = 12,650 회/s)의 90 % 미만이면 무효**, 보정 기록이 없어도 무효. **server video 는 서버 늦은 틱 > 1 % 도 무효**(P3.4 정상 0–0.38 %) | 감독 제안. 열·전원 상태로 CPU 가 느려진 실행을 잡는다 |
| 기록 | `<run>.cpu.log`: 보정값, 실행 중 1 초마다 `% Processor Performance`·전원 조절 끈 프로세스 수(실패 수) | C4 근거와 사후 확인 |
| 기준값 | 이 PC 한 대 값. 다른 PC 는 그 PC 에서 같은 루프로 다시 잰다 | |

## 측정 계획(측정 전 고정)
- 모든 측정은 gpu-watch(= measure-env)로 돌린다. C1–C4 를 적용하고, 실패·C3·C4 무효 실행은 같은 조건으로 1 회 다시 돌린다(무효 파일 보존, 보고에 적음).
- 다시 잴 것(감독 요청): (1) PR #38 의 adaptive / buffer / immediate A/B(orbit 5 회씩 + replay ×60 3 회씩) — 13:38–13:50 A/B 는 CPU 기록이 없어 C4 를 소급 판정할 수 없다. (2) P0.6 three.js 재측정(cold·orbit·replay ×60 5 회씩) — 13:52–13:57 값은 이 상태였다(frame_time p95·p99 영향 가능).

## 대가
- 측정 중인 프로세스는 효율 코어로 옮겨지지 않아 전력을 더 쓴다(측정 동안만).
- 소유자가 쓰는 상태(오전)와 쓰지 않는 상태(오후·밤)의 차이를 없애는 쪽이다 — 사용자의 실제 PC 에서 전원 조절이 걸리면 three.js(메인 스레드 해석)와 PointBlitz 모두 느려질 수 있다는 것은 공개 표 각주감이다.

## 다시 볼 조건
- 다른 PC·CPU(성능/효율 코어 구조가 다름)에서 재면 기준값을 그 PC 에서 다시 잰다.
