# 0030 브라우저 재생 클라이언트와 측정기 공용화 (P2.3)

- 상태: 승인
- 날짜: 2026-10-08
- 결정한 사람: 작업자 제안 → 감독 승인(PR #17 검토, 2026-10-08)
- 관련: 결정 0020(측정), 0026(전달 프로토콜), 0029(브라우저 뷰어), PR #6·#14 검토(탐색 전부터 메모리 표본)

## 맥락
브라우저에서 재생 서버를 따라 14 이벤트를 그린다. native 클라이언트(결정 0026)와 같은 경로·같은 마크를 쓰고, 기준 방식과 같은 측정기로 잰다.

## 선택지와 결정
| 항목 | 선택지 | 고른 것 | 이유 |
|---|---|---|---|
| 이벤트 | WebSocket / **EventSource(`/events`)** | EventSource | 기준 방식과 같은 SSE. 도착 즉시 `snapshot_received` 를 찍는다(받는 중인 전달과 무관) |
| 받기 | `arrayBuffer()` 로 한 번에 / **`response.body.getReader()` 스트림** | 스트림 | 청크가 완성되는 대로 장면에 넣는다(첫 세대는 도착하는 대로 보인다). 전체 버퍼를 한 번 더 들고 있지 않는다 |
| 청크 경계 | — | `ChunkSplitter`(`web/chunks.js`): 헤더 80 B 를 모으고 `point_count` 로 몸통 크기를 알아 청크마다 한 번 복사 | 네트워크 조각이 청크 경계와 맞지 않는다. 경계마다 자르는 단위 시험(`node --test`, CI 포함) |
| 순서 | — | 스냅샷은 도착 순서대로 하나씩 받는다(`have=세대.점 수` 는 native 와 같음) | 결정 0026 과 같은 차분 조건 |
| 표시 | — | 마지막 청크가 들어가면 다음 rAF 에서 그리고 `submitted`, `gpu_done` 이 끝나면 `presented` | native 와 같은 정의(결정 0020) |
| 워커 | 받기·나누기를 Worker 로 / **메인 스레드** | 메인 | 처음부터 워커를 쓰지 않고 측정으로 판단한다. replay ×60 에서 `main_thread_block` 0 회였다(아래) |
| 측정기 | 브라우저용 새 스크립트 / **기준 방식 `run.mjs` 에 `--target web`** | 공용 | 같은 Chrome·플래그·지표 계산(`summarize`)으로 두 구현을 잰다 |
| 메모리 표본 시작 | 탐색 뒤 / **같은 출처의 다른 주소(`/manifest.json`)를 먼저 열어 렌더러 프로세스를 만든 뒤 표본 시작 → 1 초 뒤 페이지로 이동** | 탐색 전 | PR #6·#14 검토. 이동 뒤 렌더러 프로세스가 바뀌면 경고를 낸다(이번에는 바뀌지 않음). 기준 방식 측정도 이 순서로 바뀐다 |

## 결과 (이 PC, Chrome 155 헤드리스 WebGPU, 확인용 — 판정은 P2.5)
| | replay ×60 (1 회차) | replay ×60 (2 회차) | cold |
|---|---:|---:|---:|
| preview p50 | 29.6 ms | 28.4 ms | — |
| refined p50 | 100.3 ms | 115.3 ms | 138.1 ms |
| `main_thread_block` | **0 회** | **0 회** | **0 회** |
| mem_cpu(렌더러) | 151.9 MB | 162.4 MB | 92.7 MB |
| GPU 프로세스 | 289.6 MB | | |
| bytes_total | 180,433,296 B(native 와 같음) | | |

청크 하나를 장면에 넣는 메인 스레드 시간(JS→wasm 복사 + 검증 + GPU 버퍼 생성, PR #16 검토 중간)은 가장 긴 것이 replay ×60 2.30 ms(seq 2), cold 4.00 ms(seq 14, 4 MB 청크)로 50 ms 보다 한참 작다(마크 `uploaded.chunk_max_ms`).
잘린 응답(마지막 청크 없이 끝남)은 오류로 처리한다(PR #16 검토 낮음).

14 이벤트 모두 받고·표시했다(전체·차분이 번갈아, 마지막 2,502,015 점, GPU 정점 버퍼 40,032,240 B). 오류 0.

## 대가
- 청크마다 JS 버퍼 → wasm 메모리로 한 번 더 복사된다(결정 0029). 지금은 블록이 없지만 큰 청크에서 문제가 되면 다시 본다.
- 탐색 전 페이지(`/manifest.json`)에서 브라우저가 favicon 을 요청해 404 가 콘솔에 한 번 찍힌다(측정과 무관).

## 다시 볼 조건
- `main_thread_block` 이 생기면 받기·나누기를 Worker 로 옮긴다(장면 넣기는 장치가 있는 스레드에서).
