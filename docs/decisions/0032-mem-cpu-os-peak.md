# 0032 `mem_cpu` = OS 가 기록한 프로세스 최대 commit (0020 메모리 행 대체)

- 상태: 제안
- 날짜: 2026-10-08
- 결정한 사람: 작업자(제안) → 감독 검토
- 대체: 결정 0020 표의 "메모리(`mem_cpu`)" 행(250 ms 표본의 최대). 0020 의 나머지와 "무엇을 세는가"(프로세스 private bytes, JS 힙은 보조)는 그대로다.
- 관련: PR #17 검토 H, PR #6·#14 검토(탐색 전 표본), SPEC §6.2·§7.1

## 맥락
`mem_cpu` 를 250 ms 마다 뜬 private bytes 표본의 최대로 구했다. 감독이 같은 세션 three.js cold 에서 이전 측정기 596~597 MB, 탐색 전부터 뜨는 새 측정기 536~711 MB 를 얻었다.
해석 중의 최대(약 710 MB)가 표본 사이에 끼면 놓친다. 최대가 짧을수록 더 잘 놓치므로, 빠른 구현(PointBlitz)에 유리하게 기운다.

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| 표본 간격을 줄이기(예: 10 ms) | 그대로의 방법 | 그래도 놓칠 수 있다. 표본 비용이 측정에 섞인다 |
| ETW 등 OS 추적 | 정확한 시간축 | 관리자 권한·도구 의존 |
| **OS 가 프로세스마다 기록하는 최대 commit** | 놓칠 수 없다(커널이 commit 이 바뀔 때마다 최대를 갱신). 읽기 한 번 | 프로세스가 살아 있을 때 읽어야 한다. 프로세스 전체 생애의 최대다(측정 구간만 따로 못 자른다) |

## 결정
`mem_cpu` = 측정 끝에 읽은 **`Win32_Process.PeakPageFileUsage`**(= `PROCESS_MEMORY_COUNTERS.PeakPagefileUsage`, 프로세스 commit charge 의 최대).
- browser(three.js·PointBlitz web): 렌더러 프로세스. 브라우저를 닫기 전에 읽는다(`procmem.peakCommit`). GPU 프로세스의 같은 값을 `mem_gpu_process_peak` 로 함께 싣는다(PR #13 검토).
- native: 프로세스. `--wait-before-exit` 로 결과를 쓴 뒤 `finished` 를 출력하고 기다리게 해서, 측정기가 값을 읽은 뒤 끝낸다.
- 250 ms 표본은 `mem_cpu_sampled_max` 로 남긴다(시간축 그림·교차 확인용, 판정에 쓰지 않음).
- 렌더러 프로세스는 탐색 전부터 있던 것이므로(결정 0030) 그 생애의 최대가 곧 측정 구간의 최대다. 탐색 전 페이지(`/manifest.json`)는 가볍다.

## 검증 (이 PC, three.js 페이지, 각 3 회)
| 자가 점검 | 무엇 | OS 최대(새) 증가 | 250 ms 표본(이전) 증가 |
|---|---|---:|---:|
| `memtest` | 200 MiB 를 잡고 유지 | 198.6~202.1 MB | 198.6~202.0 MB |
| `memspike`(새) | 200 MiB 를 채우고 약 30 ms 뒤 해제(`ArrayBuffer.transfer(0)`) | **201.6~202.8 MB** | **4~8 KB(놓침)** |

새 방법은 유지된 할당과 짧은 최대를 모두 잡고, 이전 방법은 짧은 최대를 통째로 놓친다.

같은 세션 cold, 참고:
| | `mem_cpu`(OS 최대) | `mem_cpu_sampled_max` |
|---|---:|---:|
| three.js(3 회) | 712.5~776.6 MB(중앙 773.7) | 622.6~712.5 MB |
| native(1 회) | 282.3 MB | 271.7 MB |

## 결과
- P0.6·P1.5 의 `mem_cpu`(three.js 597~958 MB, native 348.6 MB 등)는 낮게 잡혔을 수 있다. 문서의 값은 고치지 않고(그때의 방법으로 잰 기록), P2.5 에서 three.js·native·browser 를 같은 세션에서 이 방법으로 다시 재서 비교표의 `mem_cpu` 행을 모두 바꾼다. SPEC 목표(300 MB)는 그대로이고, native 판정이 바뀌면 그대로 보고한다.
- 측정 순서 변경(탐색 전 표본, 결정 0030)과 함께 P2.5 문서에 적는다.

## 대가
- Windows 전용이다. 다른 OS 에서 잴 때는 같은 뜻의 값(Linux `/proc/<pid>/status` 의 `VmHWM` 은 RSS 최대라 뜻이 다르다 — commit 에 해당하는 값을 따로 정해야 한다)을 결정 기록과 함께 정한다.
- 프로세스 생애 전체의 최대라 시작 비용(드라이버 초기화 등)도 들어간다. native·browser 모두 같은 조건이다.
