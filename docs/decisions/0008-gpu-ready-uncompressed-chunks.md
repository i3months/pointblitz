# 0008 클라이언트로 보내는 형식: GPU 레이아웃 무압축 청크

- 상태: 제안
- 날짜: 2026-10-07
- 결정한 사람: 작업자(제안)

## 맥락
대역폭은 제약이 아니다(INTENT 원칙 2). 기존 방식의 비용은 전송보다 해석(텍스트 헤더·27 B 비정렬 레코드)과 재업로드에 있다.

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| **GPU 레이아웃 무압축 청크** | 받은 바이트를 그대로 GPU 버퍼에 복사(해석 0), 워커·메인 어디서든 싸다 | 법선을 넣으면 PLY 보다 큼 |
| PLY 그대로 | 변환 없음 | 27 B 비정렬이라 해석 필요 |
| 압축(양자화·엔트로피) | 바이트 적음 | 해석 비용 증가, 대역폭이 제약이 아니므로 이득 없음 |

## 결정
청크 = 고정 헤더(세대 번호, 점 수, 경계 상자, 지역 원점) + 위치 `f32×3`(12 B) + 색 `u8×4`(4 B, 정렬용 패딩) = 점당 16 B.
법선은 기본 청크에서 빼고, 필요한 기능(조명 등)이 켜질 때만 별도 버퍼로 보낸다.

## 대가
- 법선을 쓰는 기능이 생기면 점당 12 B 가 더 든다.

## 다시 볼 조건
