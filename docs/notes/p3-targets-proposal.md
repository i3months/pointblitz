# P3 server video 목표 수치 — 작업자 제안 (소유자 결정 필요)

- 날짜: 2026-10-08
- 상태: 제안. SPEC 목표는 소유자 몫이다(SPEC §7.1 "서버 영상은 P3 착수 때 정한다"). 정해지면 SPEC §7.1·§9 에 옮긴다.
- 원칙: PointBlitz server video 를 재기 **전에** 정한다(SPEC §8.1). 대역폭·메모리는 기록만(INTENT 원칙 2).

## 측정 조건 (다른 목표와 같음)
`flight-01`, 이 PC(RTX 4070), 루프백, 1920×1080, 60 Hz, vsync 켬, 같은 세션 번갈아. 서버와 브라우저가 같은 PC·같은 GPU 를 쓴다(이 조건을 결과에 적는다).

## 제안 값

| 지표 | 제안 목표 | 근거 |
|---|---|---|
| `event_latency` preview p50 | ≤ 80 ms | 다른 대상의 목표(≤ 50 ms)에 인코딩 + 전송 + 디코딩 + 다음 영상 프레임까지의 기다림(60 fps 기준 최대 16.7 ms)을 더한 값 |
| `event_latency` refined p50 | ≤ 250 ms | 같은 이유로 ≤ 200 ms 에 50 ms 를 더함 |
| cold(첫 영상 프레임에 마지막 스냅샷이 보일 때까지) | ≤ 350 ms | 같은 이유로 ≤ 300 ms 에 50 ms |
| 입력 → 표시 지연 p50 / p95 | ≤ 50 / 80 ms | 서버 영상만의 지표(SPEC §6.2). 루프백에서 렌더 2 ms + 인코딩 + 디코딩 + 한 프레임 이내 |
| 영상 프레임률 | 60 fps 유지(orbit 중 떨어진 프레임 ≤ 1 %) | 화면과 같은 주기 |
| 화질: 고정 시점 SSIM(영상 프레임 대 native 캡처) | ≥ 0.95 | 이전 연구에서 소유자가 고른 기준("화질 0.95 우선"). 대역폭이 제약이 아니므로 비트레이트를 올려 맞춘다 |
| 클라이언트 `main_thread_block` | 0 회 | 다른 browser 대상과 같음 |
| 비트레이트 · 받은 바이트 · 서버 GPU 시간 · 메모리 | 기록만 | INTENT 원칙 2 |

## 정해야 하는 것
- 위 값을 그대로 쓸지, 바꿀지(소유자).
- 화질 기준 SSIM 0.95 를 "영상 대 native 캡처" 로 볼지, "영상 대 서버의 인코딩 전 프레임" 으로 볼지(작업자 의견: 사용자가 보는 결과가 중요하므로 native 캡처 대비).
